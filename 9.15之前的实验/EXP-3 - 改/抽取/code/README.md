# 元信息增补与审计脚本使用说明

本目录包含 3 个用于“论文元信息增补与结果审计”的脚本，面向如下目录结构与数据来源：

- 摘要文本：`抽取/数据结果/摘要.txt`（一个文件中包含多篇记录）
- 目标 JSON 目录：`抽取/数据结果/提取结果_by_gemini/`（约 50 篇，文件名以题名开头）

脚本均为“就地修改/审计”，建议在运行前先做好版本管理或备份。

## 脚本清单

- `augment_gemini_metadata_from_txt.py`
  - 作用：从 `摘要.txt` 中解析题名/作者/发表单位/发表时间，匹配到对应 JSON 后，补充标准化的实体与关系。
  - 特性：
    - 支持一个 txt 中包含多条记录（逐条解析）。
    - 支持多种键名/中英文冒号：`Title-题名 / 题名 / Title`，`Author-作者 / 作者 / Author`，`Organ-机构 / 机构 / Organ`，`PubTime-出版时间 / 出版时间 / PubTime`。
    - 分隔符支持：中文分号/分号/顿号/逗号。
    - JSON 结构容错：顶层对象/空数组会自动修复为标准结构 `[ {"entities": [], "relations": []} ]`。
    - 去重：对新增的 entities、relations 做简单去重，避免重复。
  - 规则：
    - 新增实体：
      - 论文（题名）、作者（每位）、发表单位（每个）、发表时间（字符串）。
    - 新增关系：
      - 作者 —撰写→ 论文（对每位作者建立）。
      - 第一作者 —隶属→ 第一单位（仅第一对）。
      - 论文 —发表于→ 发表时间（若存在）。
    - 仅对能匹配到 JSON 的论文进行增补（JSON 文件名以题名为前缀）。
    - 若作者/单位缺失，则对应关系不会生成；仍会添加可用的实体/时间与“发表于”关系。

- `audit_gemini_updates.py`
  - 作用：审计“摘要.txt 中的题名集合”与“JSON 目录中的题名（文件名下划线前缀）”是否彼此覆盖。
  - 输出：
    - JSON 文件数
    - 摘要标题条目数（含题名去空格的并集）
    - 如有 JSON 的题名在摘要里找不到，会列出未匹配的清单。

- `audit_which_three_missing.py`
  - 作用：检查每个 JSON 是否“已完成元信息增补”。
  - 判定标准（默认较宽松）：
    - 存在 论文 实体，且（存在 撰写 关系 或 存在 发表 文关系）任一。
    - 该标准用于兼容“个别文章无作者信息但有发表时间”的情况。
  - 输出：
    - JSON 文件总数 / 判定已增补 / 判定未增补 的统计。
    - 如有异常（结构/读取错误）会列出。
    - 未增补的文件名与诊断明细（是否缺论文实体/撰写/发表于）。

> 注：如需“严格标准”（必须包含撰写关系），可按需修改 `audit_which_three_missing.py` 中的判定逻辑，将 `ok = ...` 改回为“论文实体 && 撰写关系”。

## 运行环境

- Python 3.8+（建议使用你已有的 `prompt_exp` 环境）
- 无额外第三方依赖（标准库即可）

## 运行方式（PowerShell）

请在任意目录下，直接用绝对路径调用（Windows 路径含空格时请加引号）：

```powershell

& "e:\conda\envs\prompt_exp\python.exe" "e:\知识图谱构建\9.15之前的实验\EXP-3 - 改\抽取\code\augment_gemini_metadata_from_txt.py"
```

## 匹配与解析细节

- 题名匹配：以 JSON 文件名的“题名 + 下划线 + 其他信息”为约定，脚本会取下划线前的部分作为题名；匹配时优先 exact 前缀匹配，并尝试“去空格”后再匹配。
- 摘要解析：
  - 一个 txt 中可以包含多篇记录；遇到新的 `Title/题名` 行即开始一条新记录。
  - 作者/机构/时间的键名与冒号支持多种写法（中英文冒号皆可）。
  - 作者与单位的列表分隔符：`；`、`;`、`、`、`，` 均可；会进行简单清洗（去首尾空白、去常见前缀符号）。
- JSON 结构修复：
  - 顶层若是对象会自动包装为数组；顶层空数组会补 `{ "entities": [], "relations": [] }`。

## 安全与回滚

- 该工具会“就地写回”JSON 文件。建议：
  - 在运行前做一次 Git 提交或拷贝备份。
  - 确认 `摘要.txt` 的来源可靠、格式稳定。
- 如需回滚，直接从版本管理恢复或用备份覆盖即可。

## 常见问题排查

- 运行输出 `[INFO] 未找到匹配 JSON：...`：
  - 这说明该题名不在 50 篇 JSON 之列，不影响已有 50 篇的增补。
- 运行输出 `[WARN] JSON 结构异常（...）`：
  - 脚本会尝试自动修复；若仍无法修复，会跳过该篇并给出文件名。
- 某篇没有“撰写”关系：
  - 多数由 `摘要.txt` 中缺少作者字段导致。脚本不会臆造作者，仅会补充可用信息（论文、单位、时间、发表于关系）。

## 变更标准说明

- 默认的“完成增补”判定是“论文实体 + （撰写 或 发表）”。这是为了兼容确实没有作者的文章。
- 如果你的流程需要“必须有撰写”作为完成标准：
  - 打开 `audit_which_three_missing.py`，将最后 `ok = ...` 改为：
    - `ok = details["has_paper_entity"] and details["has_write_relation"]`
  - 再次运行该审计脚本即可得到严格名单。

## 联系与扩展

- 如需将匹配规则从“题名前缀”升级为“题名+第一作者”，或希望把机构匹配到具体单位编码，可在 `augment_gemini_metadata_from_txt.py` 中调整 `find_json_for_title` 逻辑。
- 如需将“第一作者-第一单位”的规则改为“作者与单位对齐映射”，可在解析阶段构造配对并在关系生成处替换即可。
